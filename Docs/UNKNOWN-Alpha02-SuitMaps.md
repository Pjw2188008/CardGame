# Alpha 0.2 문양 맵 확장

## 사용 및 설정

기존 SampleScene에서 온라인 방을 만들고 참가한 뒤 두 플레이어가 준비하고 시작합니다. 대기실은 계속 `맵: RANDOM`만 표시합니다. Host가 아래 다섯 맵 중 하나를 경기당 한 번 추첨하고 양쪽에 같은 결과를 전달합니다. 약 2초의 RANDOM MAP 공개와 턴 시작 연출이 양쪽에서 끝난 뒤 40초 타이머와 전투 입력을 허용합니다. 재경기는 준비·맵·전투 상태를 초기화한 뒤 새 값을 추첨합니다. 같은 맵이 연속으로 나오는 것도 정상입니다.

| 맵 | 확률 | 같은 문양의 일반 카드 소환 보너스 | 현재 턴 플레이어 기준 턴 효과 |
|---|---:|---|---|
| ♦ 공격의 전장 | 22.5% | 공격력 +1 | 무작위 적 유닛 피해 1, HP 0이면 파괴 |
| ♠ 제압의 전장 | 22.5% | 최대·현재 HP +1 | 무작위 적 유닛 ATK -1, 최소 0 |
| ♥ 생명의 전장 | 22.5% | 최대·현재 HP +2 | 자기 플레이어 HP +2, 기본 최대 30 |
| ♣ 번영의 전장 | 22.5% | 실제 덱에서 1장 추가 드로우 | 이번 턴 현재 마나 +1, 상한 10 |
| ★ 조커의 유희 | 10% | 문양 보너스 없음 | 기존 14종 사건 중 하나 |

Normal은 가중치 0으로 온라인 추첨에서 제외하고 기존 로컬 테스트용 기능과 씬은 보존했습니다. 문양 맵은 HP 0 또는 UNKNOWN 누적 생성 3장으로 승리하고 조커 맵만 HP 0 또는 실제 JOKER 도박 누적 성공 3회로 승리합니다. UNKNOWN은 모든 맵에서 생성·소환할 수 있으며 상대의 손패와 UNKNOWN/JOKER 진행도는 계속 숨깁니다.

추가 연결 작업은 필요하지 않습니다. 기존 NetworkManager, UnityTransport, Cloud 프로젝트, Authentication 프로필, Relay 및 패키지를 그대로 사용합니다. 네트워크 메시지는 v6이므로 양쪽 PC에 같은 새 빌드를 사용하세요.

## 효과 처리

소환 검증·마나 지불·필드 배치가 성공한 뒤 문양 보너스를 한 번 적용하고 기존 카드 고유 능력을 처리합니다. 같은 문양의 CardType.Normal만 대상이며 다른 문양·UNKNOWN·JOKER에는 소환 보너스를 적용하지 않습니다. 기본 카드 정의를 수정하지 않고 해당 런타임 인스턴스만 변경합니다. 클로버 드로우와 원래 카드 드로우 능력은 합산되며 실제 덱 잔여량·손패 10장·초과 드로우 폐기 규칙을 사용합니다.

턴 시작은 플레이어 확정 → 마나 증가·회복 → 기본 드로우 또는 빈 손패 최대 5장 보충 → 맵 효과 → 연출 완료 확인 → 40초 시작 순서입니다. 문양 효과 ID는 턴 번호이고 같은 턴의 중복 적용을 거절합니다. 대상이 없는 다이아·스페이드는 효과 없음으로 진행하며 플레이어 직접 피해는 없습니다. 스페이드는 ATK 0인 유닛도 무작위 대상에 포함하고 결과를 0으로 제한합니다. 하트 회복량은 실제 최대 HP까지로 제한하며 클로버는 최대 마나를 올리지 않습니다.

Host의 기존 BattleEngine 하나에서만 대상 추첨·피해·강화·드로우·회복·마나·승리를 판정합니다. 피해와 기존 카드 피해는 공통 DamageUnit 함수를, 능력치 변경은 기존 조커 맵 ChangeMapStats를, 드로우는 기존 Draw를 사용합니다. 별도의 맵별 BattleManager나 NetworkManager를 만들지 않았습니다. Client는 맵 정의와 공개된 확정 결과, 본인 손패만 받은 뒤 기존 애니메이션을 재생합니다.

문양 맵은 작은 맵 이름·효과 안내, Hover 상세 설명, 색상과 문양 장식으로 구분합니다. 턴 효과 알림은 1초이며 기존 타격·피해 숫자·ATK/HP 변경·순차 드로우를 재사용합니다. 하트는 실제 회복량을 초록색으로 표시하고, 클로버는 MP 증가 표시와 새 마나 칸의 짧은 빛 효과를 재생합니다. 조커 사건 알림·전용 배경·본인 JACKPOT은 유지합니다.

## Inspector와 로컬 디버그

`Assets/UNKNOWN/Battle/Resources/BattleMapSettings.asset`을 선택하면 맵 이름, 문양, 색상 HEX, Weight 및 소환·턴 효과 수치를 수정할 수 있습니다. 가중치는 10,000 단위입니다. 2,250은 22.5%, 1,000은 10%이며 전체 합계는 10,000, Normal은 0으로 유지합니다. Map ID와 같은 문양의 Suit 연결도 유지하세요. 조커의 기존 14종 사건은 별도 `JokerMapSettings.asset`에 그대로 있습니다.

Play → 로컬 테스트 실행 후 `UNKNOWN > Joker Map > Local Debug`에서 테스트 맵을 선택하고 새 게임, 같은 문양 2 카드 소환, 턴 효과 강제 적용, 승리 조건 검사를 사용할 수 있습니다. 설명에는 현재 설정 수치가 표시됩니다. 대상 없는 효과는 효과 없음으로 처리합니다. 디버그는 Editor에서만 컴파일되며 온라인 전투에서는 비활성화됩니다.

## 수정 파일과 씬

- `MapDefinition.cs`, `BattleMapSettings.cs`, Resources 설정 에셋: 6개 맵 데이터(온라인 5개 + 테스트 Normal), 가중치·효과 수치·색상.
- `RandomMapSelection.cs`: 10,000 단위 가중 추첨 및 기존 경기당 1회·재경기 초기화.
- `SuitMapRules.cs`, `BattleEngine.cs`, `JokerMapRules.cs`: 문양 소환/턴 효과, 공통 피해 처리, 맵별 승리 조건.
- `BattleEvents.cs`, `BattleProtocol.cs`: 확정 문양 효과·맵 정의·마나 증가 이벤트 및 수신자별 투영.
- `NetworkBattleController.cs`: Host 설정 로드, v6 메시지 및 기존 양쪽 연출 대기.
- `BattleUIController.Map.cs`, `.cs`, `CardAnimationController.cs`: 5종 공개 연출, 작은 맵 정보·Hover·장식과 기존 효과 재사용.
- `BattleUIController.MapDebug.cs`, `JokerMapDebugWindow.cs`: 로컬 문양 맵 디버그.
- `SuitMapTests.cs`, `JokerMapTests.cs`, `BattleUIController.SuitChecks.cs`, `BattleUIController.JokerChecks.cs`, `AttackCheckMenu.cs`, `NetworkBattleSmokeRunner.cs`: 규칙·UI·온라인 대전 검사.

기존 씬과 프리팹은 삭제·초기화하지 않았으며 새 컴포넌트 연결이 필요하지 않아 씬을 수정하지 않았습니다. 런타임 UI와 기존 전투 스크립트에 연결했습니다.

## 검증 결과

규칙 122개, Unity Play Mode 280개가 통과했습니다. Play Mode 세부 항목은 공격 UI 43, 드래그 60, 기존 PvP 회귀 22, 조커·공개 연출 106, 신규 문양 맵 49입니다. 실패 및 런타임 오류는 0개입니다.

100,000회 추첨 결과: Diamond 22,481 / Spade 22,635 / Heart 22,632 / Club 22,181 / JokerGame 10,071 / Normal 0. 경계값 0·2249·2250·4499·4500·6749·6750·8999·9000·9999도 검사하여 정확한 가중 구간을 확인했습니다. 표본 결과가 비율과 정확히 같아야 한다고 가정하지 않았습니다.

맵별 기본 보너스·다른 문양/UNKNOWN 제외·고유 능력 중첩·실패 소환 무효·다이아 대상 파괴와 빈 필드·스페이드 누적/0 제한·하트 실제 회복·클로버 상한/이월 없음·덱 소진/손패 제한·설정 복사·턴 중복 방지·양쪽 수신자 상태·모든 맵의 승리 조건과 종료 후 입력 차단을 검사했습니다. Unity에서 실제 화면 렌더, Hover, 연출 중 40초 정지 및 입력 잠금, 순차 드로우와 본인 전용 진행도를 확인했습니다.

Windows Development Build는 성공했고 컴파일 오류 0개, 빌드 경고 8개입니다. 경고에는 기존 URP 셰이더 관련 항목 등이 포함됩니다. 실제 빌드에 BattleMapSettings.asset이 포함된 것을 빌드 로그에서 확인했습니다. 검증 프로젝트와 배포 폴더의 Assembly-CSharp.dll SHA-256은 `04B34D5A3FB1FCFE06F9967B4FE6D4590B091D187282FB057FDB34C6C24A8841`로 일치합니다. 실행 파일은 `Builds/UNKNOWN/UNKNOWN.exe`입니다.

같은 PC에서 실제 Windows EXE 네 개를 두 개의 Relay 방에 연결해 다섯 경기를 완료했습니다. A 방은 개발 검사 seed 347로 3경기, B 방은 seed 4로 2경기를 진행했습니다. 재현 가능한 일반 난수 seed를 사용했으며 맵·사건·도박 결과나 승리를 강제로 지정하지 않았습니다.

| 방·경기 | 양쪽 맵 | 종료 턴 | Client 승리 조건 | 확인된 맵 처리 |
|---|---|---:|---|---|
| A 1차전 | Diamond | 10 | UNKNOWN 3장 | 턴 효과 10회, 실제 적 유닛 피해 총 9 |
| A 재경기 | Heart | 10 | UNKNOWN 3장 | 턴 효과 10회, HP 최대치 제한 |
| A 3차전 | Spade | 10 | UNKNOWN 3장 | 턴 효과 10회, 공개 ATK 변경 일치 |
| B 1차전 | Club | 18 | UNKNOWN 3장 | 턴 효과 18회, 실제 임시 마나 합계 +14, 추가 드로우 |
| B 재경기 | JokerGame | 28 | JOKER 도박 성공 3회 | 사건 28회, 새 JOKER 총 9장 |

총 76턴에서 효과 ID 중복 없이 현재 턴마다 하나의 맵 효과 또는 조커 사건이 기록됐습니다. 다섯 경기 모두 양쪽 최종 공개 상태, 전체 공격 결과, 공개 피해·능력치·회복·마나 이벤트 결과가 일치했습니다. Host의 누적 맵 추첨 횟수는 방별 1→2→3 / 1→2였고 Client는 항상 0회였습니다. 경기당 공개 연출은 각 1회, 연출 중 입력 잠금·40초 유지, 대기실 결과 숨김, 수동 맵 변경 API 제거, 새 경기 상태 초기화, 상대 손패·진행도 비공개, 실제 카드 뷰·승패 UI 일치, 대기실 복귀가 모두 통과했습니다. 각 방의 마지막 경기 후 양쪽 방 나가기까지 확인하고 테스트 EXE를 종료했습니다. 중간 경기 JSON의 cleaned=false는 같은 세션으로 재경기하기 위해 방을 유지한 기록입니다.

이번 실제 Heart 경기에서는 플레이어 HP가 최대치여서 양의 회복량은 발생하지 않았습니다. HP 25→27, 29→30, 상대 HP 불변 등의 실제 회복·제한·양쪽 상태 투영과 초록색 +2 연출은 규칙 및 Play Mode 검사로 따로 확인했습니다. 모든 맵의 HP 0 승리도 규칙 검사로 확인했고, 위 온라인 경기들은 표에 적힌 조건으로 종료됐습니다.

네 EXE는 서로 다른 익명 Player ID(default / unknown_local_2 / unknown_local_3 / unknown_local_4)를 사용했으며 Project ID와 production 환경은 일치했습니다. 인증 토큰이나 비밀 키는 증거 로그에 포함하지 않았습니다. [온라인 결과 요약](Validation/SuitMaps-Alpha02/RelaySummary.json), 경기별 Host/Client JSON, 연결·맵 추첨 로그, 규칙·Play Mode 결과 및 실제 렌더 PNG는 `Docs/Validation/SuitMaps-Alpha02/`에 있습니다.

남은 검증 범위는 서로 다른 실제 PC·외부 네트워크, 인위적인 고지연·패킷 손실, 실제 마우스로 대기실을 조작하는 수동 검사입니다. 온라인 검사는 실제 Authentication/Session/Relay/Netcode를 사용하는 자동 EXE 대전이며 화면은 Unity Camera.Render로 확인했습니다. 현재 확인된 C# 컴파일 오류와 런타임 오류는 없습니다. 원본 에디터는 종료하지 않고 설치된 동일 패키지를 사용하는 별도 검증 프로젝트에서 컴파일·Play Mode·빌드를 실행했습니다.
